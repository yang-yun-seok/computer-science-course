- 작성일: 2026-09-21
- 상태: 2차 보강 구현·배포·공개 URL 검증 완료

- 유지할 기준: 기존 교안의 친절한 문체, 한국어의 자연스러운 줄바꿈, 주제 사이의 여백, 개념과 직접 연결되는 그림

## 1. 목표와 범위

학생이 배운 범위를 정해 시험을 치르고, 제출한 뒤 부족한 개념을 확인하고, 해당 설명·실습으로 돌아가 다시 익히는 흐름을 만든다. 그림의 읽기 품질을 유지하면서 첫 화면과 단원 이동에 불필요한 이미지 전송을 줄인다.

| 작업 | 이번 구현에 포함할 내용 | 완료했을 때의 모습 |
| --- | --- | --- |
| 시험 | 범위 선택, 제한 시간, 문제 이동, 검토 표시, 답안 저장, 제출, 일괄 채점, 응시 기록 | 학생이 처음부터 제출까지 하나의 시험을 치를 수 있다. |
| 복습 | 기존 확인 문제·시험의 오답 모으기, 재도전, 개념·실습 연결, 핵심 세 가지 | 틀린 이유를 읽고 학습한 뒤 다시 확인할 수 있다. |
| 이미지 | 실제 사용 파일 점검, 크기·형식 최적화, 웹용 외부 파일 분리, 지연 로딩 | 읽지 않은 단원의 이미지는 처음부터 내려받지 않는다. |

일반적인 강의 진도율·수강 완료·이어보기는 앞서 제안한 2번에 해당하므로 이번 범위에 추가하지 않는다. 시험 답안과 복습 상태 저장은 위 기능에 필요한 범위에서 구현한다. 용어 정리 예시 추가도 별도 후속 작업으로 남긴다.

교사용 성적 수집, 계정, 기기 간 동기화, 감독·부정행위 방지, 공식 수료증은 이번 범위에 포함하지 않는다. GitHub Pages의 정적 사이트에서 실행하는 자기 점검용 시험으로 설계한다. 정답과 기록을 브라우저에서 확인하거나 수정할 수 있으므로 공식 성적의 진위를 보장하는 구조로 설명하지 않는다.

2026-09-21 로컬 소스·빌드 산출물을 읽어 확인했다. 아래 수치는 최적화 결과가 아닌 작업 전 기준이다.

| 항목 | 현재 상태 | 작업에 미치는 영향 |
| --- | --- | --- |
| 교안 | 24개 대단원, 48개 소단원 | 1강 CH01~06 / 2강 CH07~12 / 3강 CH13~20 / 부록 CH21~24 분류를 유지한다. |
| 확인 문제 | 총 144개, 선택 즉시 채점·해설 가능 | 기존 확인 문제는 유지하고 시험과 복습에 필요한 식별자를 부여한다. |
| 문제 데이터 | `q`, `options`, `answer`, `feedback`, `review` | 정답·선택지별 해설·본문 복습 위치를 공통 데이터로 연결할 수 있다. |
| 화면 이동 | `src/app.js`의 해시 라우팅 | 시험·결과·복습 주소를 기존 라우터에 추가한다. |
| 저장 | 현재 확인 문제의 응답 이력 저장 없음 | 강의 실습 저장소와 구분되는 시험·복습 전용 저장소가 필요하다. |
| 이미지 | 실제 참조 JPEG 18개, 합계 2,332,061바이트 | 33.89MiB의 PNG 원본 전체가 현재 배포되는 것은 아니다. |
| HTML | `dist/index.html` 5,470,379바이트, 약 5.22MiB | JPEG도 Base64로 HTML에 포함되어 첫 문서 전송에 함께 들어간다. |
| 빌드·배포 | `scripts/build.cjs`가 단일 HTML 생성, Actions가 `dist/` 게시 | 웹 배포용 파일 분리와 보관용 단일 HTML을 각각 만들 수 있다. |

현재 이미지가 내장된 상태에서 `loading="lazy"`만 추가하면 첫 HTML의 이미지 바이트는 줄지 않는다. 웹 배포판에서 이미지 파일을 분리하는 작업을 최적화의 핵심으로 잡는다.

## 3. 학생이 이용할 화면과 이동

목차의 기존 개요·강의·부록·용어 정리 순서를 유지하고, 용어 정리 아래에 **시험 보기**, **복습 노트**를 추가한다. 개요와 소단원 하단에는 해당 범위의 시험으로 이동하는 작은 링크를 둔다.

```text
시험 보기 → 시험 선택 → 범위·시간 확인 → 응시 → 제출 전 확인 → 결과
                                                        ↓
                        다시 시험 보기 ← 해설·본문·실습 ← 복습 노트
```

| 주소 기본안 | 화면 | 핵심 내용 |
| --- | --- | --- |
| `#exams` | 시험 목록 | 단원별·과정별·전체 시험, 진행 중 시험, 최근 응시 기록 |
| `#exam/setup/<presetId>` | 시작 안내 | 범위, 문항 수, 제한 시간, 제한 시간 없이 응시 선택 |
| `#exam/run/<attemptId>` | 응시 | 한 번에 한 문제, 이전·다음, 문제 번호 목록, 남은 시간, 검토 표시 |
| `#exam/result/<attemptId>` | 결과 | 점수, 정답·오답·미응답 수, 소요 시간, 단원별 결과, 해설 |
| `#review` | 복습 노트 | 미해결 오답, 미응답, 해설만 본 문제, 복습 완료 항목 |

경로는 구현 시 확정하되 기존 `#ch01-l01/b04`, `#overview/learning-path`, `#glossary` 주소가 계속 동작해야 한다. 결과 주소의 기록이 현재 브라우저에 없으면 목록으로 돌아갈 수 있는 안내를 보여준다.

### 응시 화면의 배치

```text
1강 시험                       7 / 20문항        남은 시간 21:35
──────────────────────────────────────────────────────────────
문제 상황과 필요한 그림·표

○ 선택지 1
○ 선택지 2
○ 선택지 3
○ 선택지 4

[이전 문제]                  [검토 표시]          [다음 문제]

문제 번호 목록: 답변함 / 미응답 / 검토 필요
                                         [답안 확인 후 제출]
```

- 문제 본문과 선택지 사이, 다음 동작 영역 사이에 충분한 여백을 둔다.
- 응시 중에는 정답·해설을 노출하지 않고 제출 후 한꺼번에 공개한다.
- 다른 문제로 이동해도 선택한 답과 검토 표시가 유지된다.
- 문제 번호 상태는 색뿐 아니라 글자·기호·접근 가능한 이름으로 구별한다.
- 모바일에서는 문제를 먼저 보여주고 번호 목록을 접어 둘 수 있게 한다. 고정 도구막대가 선택지나 제출 버튼을 가리지 않게 한다.
- 키보드만으로 선택·문제 이동·제출할 수 있게 한다. 시간 알림은 매초 읽지 않고 남은 5분·1분과 종료 시점에 제공한다.

## 4. 시험 구성과 문제 제작

### 4.1 시험 기본안

| 시험 | 범위 | 출제 수 | 기본 시간 | 배분 규칙 |
| --- | --- | --- | --- | --- |
| 단원별 시험 | 선택한 대단원의 두 소단원 | 10문항 | 15분 | 소단원마다 5문항 |
| 1강 시험 | CH01~06 | 20문항 | 30분 | 12개 소단원에서 최소 1문항씩 |
| 2강 시험 | CH07~12 | 20문항 | 30분 | 12개 소단원에서 최소 1문항씩 |

시간은 실제로 읽고 풀어 보는 시범 검증 후 조정한다. 모든 시험은 시작 전에 ‘제한 시간 없이 응시’를 고를 수 있게 하고 기록에서 구분한다. 응시 중 시간 설정을 바꾸거나 일시 정지하지 않는다.

최소 배분 후 남은 문항은 아직 적게 출제된 소단원을 우선하며, 동률은 저장한 난수 시드로 선택한다. 같은 시험에 같은 문제가 두 번 나오지 않게 한다. 유형은 가능한 범위에서 개념 구별 30%, 동작 예측 40%, 상황 적용 30%를 목표로 하되 단원 범위와 최소 배분을 우선한다.

### 4.2 문제은행 제작량과 기준

- 기존 확인 문제 144개는 본문 학습과 복습용으로 유지한다.
- 시험 전용 문제는 소단원당 6개, 총 **288개를 새로 작성**하는 기본안이다. 실제 완성 수량과 구별하여 진행표에 기록한다.
- 소단원당 개념 구별 2개, 동작·결과 예측 2개, 상황 적용 2개를 준비한다.
- 초기 시험 유형은 정답이 하나인 선택형으로 통일한다. 상황·그림·표·짧은 코드·실행 순서를 읽는 문제를 포함해 이해와 적용을 평가한다.
- 문구나 숫자만 바꾼 같은 문제를 여러 문항으로 세지 않는다. 본문의 확인 문제와 같은 답을 기억하는 것만으로 풀리지 않게 상황을 바꾼다.
- 모든 선택지에는 이유를 쓴다. 정답 이유, 대표 오해, 다시 읽을 본문 위치가 일치해야 한다.
- 구현마다 달라지는 동작은 문제 안에 전제 조건을 명시한다. ‘항상’, ‘무조건’ 같은 표현을 검토한다.
- ‘위의 모든 답’, ‘앞의 두 항목’처럼 선택지 순서에 의존하는 문구를 피한다. 순서가 의미를 갖는 경우 선택지 섞기를 끈다.
- 그림은 답을 이해하는 데 필요한 경우 사용한다. 기존의 소단원별 이미지·도해 수를 억지로 시험 문항마다 적용하지 않는다.
- 서술형 자동 채점과 실행형 코딩 시험은 후속 기능으로 남긴다.

| 집필 묶음 | 소단원 수 | 신규 시험 문제 | 검토·공개 조건 |
| --- | --- | --- | --- |
| 1강 | 12 | 72 | CH01의 12문항으로 시험 전체 흐름을 먼저 검증한 뒤 확장 |
| 2강 | 12 | 72 | 계산·순서·조건에 따른 결과를 독립적으로 확인 |

시범 구현은 개발 확인에만 사용한다. 공개 시험 버튼은 해당 시험 범위를 채울 검토 완료 문제가 준비된 뒤 활성화한다. 부족한 문제를 중복 출제하거나 문항 수를 몰래 줄이지 않는다.

## 5. 응시·제출·채점 규칙

### 5.1 응시 상태

`준비 → 응시 중 → 제출 확인 → 제출 완료`를 기본 흐름으로 삼는다. 시간 종료도 동일한 제출 처리로 들어간다. 명시적인 ‘응시 종료’로 포기한 기록은 채점된 결과와 구분한다.

1. 시작을 누른 시점에 출제 목록·선택지 순서·시작 시각·종료 예정 시각을 확정해 저장한다.
2. 답 변경, 검토 표시, 문제 이동 직후 현재 상태를 저장한다. 저장을 페이지 종료 이벤트에만 의존하지 않는다.
3. 남은 시간은 `종료 예정 시각 - 현재 시각`으로 계산한다. 탭이 비활성화되거나 화면이 잠겨도 시간이 멈춘 것으로 처리하지 않는다.
4. 새로고침하거나 다시 접속하면 같은 문제와 답안을 복원한다. 이미 시간이 지났다면 추가 답변을 받기 전에 저장된 답안으로 제출 처리한다.
5. 앱 내부 이동 시 ‘시험 계속하기 / 나가기’ 안내를 제공한다. 나가더라도 제한 시간이 흐른다는 점을 짧게 알린다. 브라우저 종료 확인창 표시 자체를 저장 보장 수단으로 삼지 않는다.
6. 한 브라우저에서 진행 중 시험은 하나만 둔다. 다른 탭에서 같은 시험을 열면 응시 소유 탭을 확인하고 읽기 전용으로 안내한다. 명시적 이어받기를 하면 이전 탭의 쓰기·제출을 막는다.
7. 저장소가 차단되거나 가득 차면 현재 화면에서는 계속 응시할 수 있게 하고, 새로고침 시 기록을 복원하지 못할 수 있음을 안내한다.

PC 시계 변경을 이용한 시간 조작까지 막을 수는 없다. 탐지 가능한 큰 시간 변화는 기록하되 공식 시험 감독 기능으로 확대하지 않는다.

### 5.2 제출과 점수

- 수동 제출 전 ‘답변 17개 / 미응답 3개 / 검토 표시 2개’처럼 확인 정보를 보여준다. 미응답이 있어도 제출을 선택할 수 있다.
- 시간 종료 시에는 확인창을 기다리지 않고 자동 제출한다. 종료 이후 선택지 입력은 받지 않는다.
- 각 문항은 같은 배점이다. 점수는 `정답 수 / 전체 문항 수 × 100`을 소수점 첫째 자리로 표시한다.
- 오답과 미응답은 0점이지만 결과에서는 따로 센다. 감점·부분 점수는 두지 않는다.
- 제한 시간 0초 경계의 답변 변경과 제출 요청은 같은 종료 확인 로직을 거친다.
- 제출 버튼 중복 클릭·타이머 종료·다른 탭의 요청이 겹쳐도 하나의 응시 ID에는 결과를 한 번만 확정한다.
- 제출한 답안은 수정하지 않는다. ‘다시 시험 보기’는 새 응시 기록을 만든다.
- 합격·불합격 기준이나 학생 간 순위는 임의로 만들지 않는다. 맞힌 개수와 복습할 개념을 중심으로 보여준다.

### 5.3 결과 화면

점수와 정답·오답·미응답 수, 소요 시간, 제출 방식(직접 제출/시간 종료), 응시 시간 설정을 표시한다. 단원별 결과에는 `2/3문항`처럼 표본 수를 함께 보여주며 적은 문항으로 숙련도를 단정하지 않는다.

각 문제에서 학생의 선택, 정답, 선택지별 해설, 관련 본문·실습 링크를 제공한다. 오답 또는 미응답만 걸러 볼 수 있게 한다. ‘오답 복습하기’와 ‘새 시험 보기’로 다음 행동을 연결한다.

## 6. 퀴즈 복습 기능 — 앞서 제안한 3번

### 6.1 복습 항목을 만드는 시점

| 행동 | 기록 | 복습 상태 |
| --- | --- | --- |
| 기존 확인 문제에서 오답 제출 | 선택한 답·문제 ID·시각 | 다시 풀 문제 |
| 답을 고르지 않고 해설 보기 | 해설 열람 사실 | 해설을 본 문제, 정답 처리하지 않음 |
| 시험에서 오답·미응답 | 제출한 시험의 문제·응답 | 제출 확정 후 복습 대상으로 추가 |
| 해설을 닫은 재도전에서 정답 제출 | 재도전 결과 | 복습 완료 |
| 복습 완료 후 다시 오답 | 새로운 응답 | 다시 풀 문제로 복귀 |

같은 문제를 여러 번 틀려도 복습 목록에는 하나로 모으고 최근 시도·오답 횟수를 갱신한다. 시험 응시 기록은 별도로 보존한다. 해설을 본 상태에서 정답을 눌렀다는 이유만으로 복습 완료로 바꾸지 않는다.

### 6.2 복습 화면의 흐름

1. 단원과 출처(확인 문제/시험), 상태로 목록을 좁힌다.
2. ‘다시 풀기’에서는 이전 선택과 정답·해설을 숨긴다.
3. 제출하면 틀린 이유와 정답 이유를 함께 보여준다.
4. ‘설명 다시 읽기’는 해당 소단원의 정확한 주제로 이동한다. 실습이 있으면 실습 위치도 연결한다.
5. 본문에서 복습 노트의 해당 문제로 돌아갈 수 있는 링크를 제공한다. 새로고침에도 복귀 경로가 유지되게 한다.
6. 관련 소단원의 기존 `summary`를 사용해 ‘핵심 세 가지’를 보여준다. 시험 정답만 외우도록 요약을 새로 축약하지 않는다.

오답이 없을 때는 빈 화면 대신 시험·확인 문제로 연결한다. ‘복습 완료’는 재도전에서 정답을 제출했다는 뜻이며 영구적인 개념 습득의 증명으로 설명하지 않는다.

### 7.1 데이터 계약 기본안

- 기존 확인 문제에도 영구 ID를 소스에 직접 부여한다. 배열 순서나 문장 문자열을 ID로 쓰지 않는다.
- 선택지 ID와 정답 ID를 연결한다. 선택지 순서를 섞어도 채점이 달라지지 않아야 한다.
- 문제은행을 수정해도 지난 성적이 다시 계산되지 않도록 응시 당시 자료를 보관한다. 오류가 수정된 옛 문제는 새 버전 복습으로 안내한다.
- 저장 키에는 사이트 고유 접두사와 `schemaVersion`을 둔다. 강의 실습의 저장 키와 충돌하지 않게 한다.
- `localStorage`를 기본으로 하되 직렬화·저장 실패를 처리하는 공통 어댑터를 둔다. 저장 내용은 읽을 때 구조·범위를 검증하고 학생 입력은 텍스트로 렌더링한다.
- 최근 완료 응시 20회를 기본 보관 한도로 제안한다. 한도를 안내하고 오래된 기록을 정리해도 미해결 복습 항목은 보존한다. 진행 중 시험은 자동 정리하지 않는다.
- ‘이 브라우저에 기록이 저장돼요’와 기록 삭제 기능을 제공한다. 삭제 범위를 선택·확인하게 하고 다른 사이트나 실습의 저장 데이터는 지우지 않는다.
- 손상·지원하지 않는 미래 버전 데이터는 덮어쓰지 않고 복구 안내를 제공한다. 기록이 없어도 교안과 시험 시작 화면은 정상 표시한다.

## 8. 이미지 최적화 — 앞서 제안한 4번

### 8.1 먼저 측정할 항목

- 실제 참조 이미지와 보관용 원본을 구별한다. 파일 수·치수·바이트·사용 단원·반복 사용 여부를 목록화한다.
- 개요, CH01~03의 이미지가 많은 단원, SVG 도해 중심 단원, 용어 정리, 시험 시작 화면을 비교 대상으로 잡는다.
- 캐시를 비운 첫 방문과 재방문을 구분해 HTML 크기·이미지 요청 수·전송량·화면 표시 상태를 기록한다.
- 네트워크·뷰포트 조건을 고정한다. 미압축 파일 바이트와 브라우저의 압축 전송량을 혼동하지 않는다.

### 8.2 산출물 분리

| 산출물 | 이미지 처리 | 용도 |
| --- | --- | --- |
| `dist/index.html` + `dist/assets/` | 필요한 크기의 외부 이미지 참조 | GitHub Pages 기본 페이지 |
| `dist/cs-course.html` | 최적화한 이미지 내장 | 기존 단일 파일 보관·전달용 |

웹판의 이미지 경로는 `./assets/...`를 기준으로 만든다. `/assets/...`처럼 도메인 루트에 고정하지 않아 `/computer-science-course/` 아래에서도 동작하게 한다. 파생 파일명에 콘텐츠 해시를 붙여 교체된 이미지가 이전 캐시에 남지 않게 한다. 오래된 파생본이 배포 폴더에 누적되지 않도록 빌드가 생성 파일 목록을 관리한다.

### 8.3 품질을 유지하는 최적화 순서

1. 실제 배치 폭을 기준으로 필요한 크기만 생성한다. 초기 후보는 640px·960px·1280px이며 원본보다 확대하지 않는다.
2. WebP와 기존 JPEG를 같은 표시 크기로 비교한다. WebP가 더 작고 그림의 선·표정·작은 글자를 유지하는 경우 채택한다. 불리한 이미지는 JPEG 또는 PNG를 유지한다.
3. `picture`·`srcset`·`sizes`로 화면 폭에 맞는 파일을 선택한다. 이미지의 `width`·`height` 또는 비율을 지정해 로딩 중 본문 위치가 크게 변하지 않게 한다.
4. 처음 보이는 핵심 그림은 즉시 불러오고 아래쪽 그림은 지연 로딩한다. 시험의 현재 문제 그림은 즉시 표시하되 전체 시험 그림을 미리 받지 않는다.
5. 기존 SVG 개념 도해는 벡터로 유지한다. 그림을 삭제해 단원별 이해 자료 수를 줄이거나 무조건 저해상도로 낮추지 않는다.
6. 대체 텍스트·캡션이 실제 그림과 앞 문단의 개념에 맞는지 확인한다. 내용을 이해하려고 그림 안의 작은 글자만 읽어야 하는 경우 설명을 본문에도 둔다.
7. 생성 PNG 원본과 프롬프트 기록은 보존한다. 배포 폴더에는 필요한 파생 파일만 복사한다.

### 8.4 성능·품질 완료 기준

- 같은 최종 콘텐츠를 내장한 비교용 HTML보다 웹판의 초기 HTML 바이트를 **30% 이상 줄이는 것**을 목표로 한다. 달성 여부와 실제 수치를 기록하고 미달 원인을 남긴다.
- 개요 첫 방문에서 읽지 않은 소단원의 래스터 이미지 요청이 발생하지 않는다.
- 좁은 화면에서 적절한 파생 크기가 선택되고, 단원 이동·새로고침·깊은 링크 진입 시 이미지 누락이 없다.
- 대표 그림을 데스크톱·모바일·200% 확대에서 비교해 설명에 필요한 글자와 선을 식별할 수 있다.
- 이미지 박스의 크기가 로딩 전에 확보되고 캡션·버튼이 뒤늦게 크게 밀리지 않는다.
- 단일 파일판에 웹판 전용 외부 이미지 경로가 남지 않는다. 파일 직접 열기 검증이 도구 정책상 불가능하면 실행 확인과 정적 검사를 구분해 기록한다.

순수 계산·상태 전이·저장 경계는 자동 검사로 확인하고, 실제 응시·복습 이동·읽기 품질·이미지 요청은 브라우저에서 확인한다. 문서 작성 단계에서는 테스트나 배포가 완료된 것으로 표시하지 않는다.
