## 판단 기준

- 그림의 대상, 개수, 순서와 숫자가 바로 앞뒤 설명을 따르는가.
- 화살표가 이동·참조·소유·방문 순서 중 무엇을 나타내는지 알 수 있는가.
- 중간 상태와 완료 상태를 구분하고 값이나 행을 빠뜨리지 않는가.
- 비유의 색·거리·크기를 실제 수치나 하드웨어 배치로 오해하지 않는가.
- 새 개념을 설명하면서 정의하지 않은 다른 문제로 바뀌지 않는가.
- 좁은 화면에서도 이름·결과·캡션을 읽을 수 있는가.

## 화면과 회귀 검증

- 48개 교안의 188개 그림과 별도 도해 15개를 기본 데스크톱 및 320px에서 점검했다. 최초 모바일 검수의 잘림 5곳을 고쳤다.
- 주요 수정 도해 19곳은 실제 화면을 촬영해 값·선·라벨·캡션의 배치를 육안으로 확인했다. 이미지·사진 21개는 교체 전 원본까지 열어 주변 설명과 대조했다.
- 도해 기본 스타일의 높은 선택자 우선순위가 개별 grid 배치를 덮던 문제를 `:where()`로 해결했다. 새 도해는 기존 파일 안의 HTML·SVG로 작성했으며 런타임 모듈·의존성을 추가하지 않았다.
- 공유 스타일과 재사용 그림의 영향은 핵심 용어 290개의 **실제 열린 상세 영역**을 데스크톱·320px에서 각각 확인했다. 숨겨진 상세 영역의 크기는 판정에서 제외했다. 작은 셀의 글자 넘침과 페이지 폴트 도해의 읽기 순서도 보완했다.
- 독립 계산으로 비트·연속 빈 공간·배열 확장·해시·이진 탐색·동전 DP·BST·힙·BFS/DFS·유실 갱신·무손실 분해·JOIN·FIFO/LRU·파이프라인·암달 법칙을 확인하는 테스트와 검수대장 누락 검사를 추가했다.
- `npm test`: **285개 통과**. `npm run build`: 웹 배포본·단일 HTML 생성 성공.

실제 초심자 수업에서 이해도를 측정한 결과는 아니다. 편집 검수·수치 검증·브라우저 확인 결과이며, 수업에서는 어느 라벨이나 단계에서 멈추는지 추가로 관찰할 수 있다.
