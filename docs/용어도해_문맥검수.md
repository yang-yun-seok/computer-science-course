## 주요 수정

- **명령어·제어 신호:** CPU 부품 목록을 재사용하던 그림을 읽기·계산·기록 및 신호의 대상·역할로 나눴다. 기계어·어셈블리어는 비트 무늬 대신 실제 RISC-V `add x5, x6, x7`과 32비트 인코딩을 대응시켰다. 필드 이름은 한국어로 풀었다.
- **메모리·프로세스:** Data와 BSS를 분리해 초기값 100과 0의 차이를 보였다. 준비/실행/대기는 실제 전이 경로로, 준비 큐와 CPU 버스트는 입출력 대기와 구별했다. 요구 페이징은 아직 필요하지 않은 페이지를 남겨 두는 모습으로 바꿨다.
- **자료구조:** 인덱스 0·1·2와 길이 3, 트리의 깊이·높이 값과 서브트리 경계, 값이 있는 BST, 완전한 힙의 실제 모양을 표시했다. 인접 행렬에 행·열 이름을 달고 BFS·DFS는 같은 그래프에서 여섯 정점을 모두 방문하는 순서를 보여 준다.
- **데이터베이스:** 같은 3이던 행 수·열 수를 4행·3열로 나눴다. SELECT가 요구한 이름·레벨과 결과 열을 맞추고 스키마·실제 데이터, 후보/기본/외래 키, 인덱스·원래 레코드의 연결을 표시했다. ACID 네 성질과 제약 준수, 하나의 격리 수준에서 실제로 읽히는 값을 분리했다.
- **네트워크:** 중첩 상자에 계층·헤더·전달 단위의 이름을 달았다. TCP 세그먼트 1480B와 IP 패킷 1500B를 나누고 순서 번호·누적 ACK·재전송 이후 결과를 이어 보였다. 경로 MTU에는 피드백을, 혼잡에는 라우터 출력 링크와 유한 큐를 표시했다.
- **웹·DNS:** 도메인의 계층과 실제 자원 레코드, URL의 게임 예시 주소와 요청 대상을 표시했다. 지속 연결은 같은 TCP 연결 재사용으로, 소켓은 양쪽 프로세스의 끝점으로 그렸다. Web Storage의 두 종류, 쿠키의 Secure·HttpOnly와 서버 세션의 역할을 구분했다.

## 확인한 수치·절차

- `10001010₂ = 128 + 8 + 2 = 138₁₀`, 8비트 2의 보수 −5와 부호 없는 251 해석.
- RISC-V 명령 필드로부터 opcode·입력/결과 레지스터를 복원해 `add x5, x6, x7`과 일치함을 검사.
- 같은 그래프의 BFS `A B C D E F`, DFS `A B D E C F`. 이웃 순서는 알파벳 순으로 고정.
- 4행·3열, 레벨 조건으로 남는 2행, 인덱스가 가리킨 위치와 원래 레코드의 ID 일치.
- 빈 프레임의 LRU에서 `ABC` 네 번 반복: 2프레임은 12/12, 3프레임은 3/12 폴트.
- TCP에서 A100·C102만 받았을 때 ACK101, B101 복구 뒤 ACK103. 이는 앱의 구매 성공 확인과 구별.
- IPv4 20B + TCP 20B + 데이터 1460B = IP 패킷 1500B. 대역폭 상한과 실제 처리율, 전송 시간의 단위 구별.
