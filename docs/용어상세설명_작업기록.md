## 학생이 읽는 순서

1. 교안에서는 기존의 짧은 뜻을 팝업으로 읽는다.
2. ‘용어 정리에서 자세히 보기’를 누르면 해당 항목의 상세 설명이 열린다.
3. 기본 뜻 아래에서 개념 도해, 두 문단의 원리 설명, 게임 속 예시, 헷갈리는 개념과의 차이를 읽는다.
4. 설명 아래의 복귀 링크로 원래 교안의 주제와 용어 위치로 돌아간다. 복습·종합 사례의 복귀 정보도 보존한다.

용어 목록에서는 네이티브 `details`로 설명을 접고 펼친다. 상세 설명을 펼친 동안 검색 도구는 상단을 계속 덮지 않도록 했다. 기존의 짧은 정의와 긴 설명은 별도 데이터로 관리한다.

## 설명 원칙

- 정의를 길게 반복하는 대신 역할·동작·이유를 두 문단으로 풀었다.
- 전투의 체력 계산, 아이템 구매, 인벤토리, 랭킹, 맵 이동, 채팅, 서버·패치 상황을 개념에 맞춰 사용했다.
- 주소·바이트·작업 수·그래프 비용처럼 작은 수를 직접 따라갈 수 있는 예시를 넣었다.
- IR·IPC·BSS·Clock·TTL, 배열/DB 인덱스, 자료구조/메모리 힙, 웹/브라우저 세션의 뜻을 구별했다.
- ACK 수신과 아이템 지급 성공, DB 커밋과 외부 효과, 쓰기 호출과 영구 반영을 같은 완료로 다루지 않았다.
- 설명에 새로 필요한 용어는 짧게 풀었다. 실제 CPU·OS·언어·DBMS별 차이는 필요한 범위에서 밝혔다.

## 시각 자료 보강 — 2026-10-31

마우스 오버 팝업은 짧은 뜻을 유지하고, 용어 정리의 펼친 상세 설명 맨 앞에 ‘그림으로 이해하기’를 추가했다. 같은 핵심 290개 모두에 시각 자료를 연결했다.

- 130개 항목에는 57종의 전용 도해를 사용한다. RAM의 실행·저장·전원 종료, CPU 구성, 프로세스 문맥 교환, 캐시 교체, 메모리 할당, 플레이어 표와 조인, 구매 거래, 패킷 크기, 전송 시간 등을 작은 수로 그렸다.
- 160개 항목에는 기존 교안의 그림 68개를 재사용한다. 트리·그래프·페이지 변환·파이프라인·네트워크 계층처럼 본문과 연결되는 그림을 사용하고, 위에 어느 부분을 봐야 하는지 안내한다.
- RAM에는 세 장면의 도해 아래에 실제 PlayStation RAM 칩 사진도 넣었다. 기존의 사진 출처·CC BY-SA 4.0·잘라낸 부분 표기를 유지한다. 이더넷 스위치 사진도 기존 출처를 유지한다.
- 사진으로 설명하기 어려운 순서·관계·수량은 표, 노드와 간선, 시간표, 메모리 칸, 중첩 상자, 패킷 구간으로 표현한다. 색만으로 구별하지 않고 값·이름·화살표·캡션을 함께 쓴다.
- CPU 캐시의 LRU 예시, 8비트 2의 보수, 옵션 없는 IPv4/TCP, 단편화의 IPv6 차이, TTL과 홉 제한, 저장 완료와 휘발성 등 도해의 가정과 범위를 캡션에 밝혔다.
- 도해 등록은 `content/glossary-visuals.js`, 렌더링은 `src/glossary-visuals.js`로 분리했다. 팝업 모듈과 기본 정의 데이터에는 도해를 넣지 않았다.
- 기존 그림의 배열·스택·큐·그래프·캡슐화·가상 머신 비교를 용어집의 좁은 폭에 맞췄다. 파이프라인은 명령별 행과 사이클 열을 맞추고 좁은 화면에서는 그림 안에서 스크롤한다.
- 전체 자동 검사 263개, 웹·단일 HTML 빌드 통과. 새 검사 6개는 290개 범위, 그림 참조와 중복 ID, 사진 출처, 핵심 수치와 정책 차이, 팝업 분리를 확인한다.
- 브라우저에서 390px 및 320px의 290개 직접 주소를 확인했다. 320px에서 잘리던 17개 항목은 수정 후 다시 검사해 페이지 가로 넘침·그림 잘림·도해 누락이 없음을 확인했다. 데스크톱 RAM 도해와 사진 로딩도 확인했다.
