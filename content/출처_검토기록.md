# 원본·정확성 검토 기록

확인일: 2026-09-15. 기존 노션의 목차와 펼친 텍스트를 브라우저에서 읽고 학생용 설명을 새로 집필한다. 원본 그림을 복제하지 않고 자체 도해를 만든다. 기술 설명에 오류가 있는 경우 비유의 역할은 살리되 사실을 수정한다.

- 기존 초안 검토: 완료
- 확인: 컴퓨터 구성, 입력·출력, CPU 구성과 동작, 레지스터 상세, 클럭·코어, 메모리 계층과 SRAM/DRAM, 보조기억장치, 하버드/폰 노이만, SoC 사례, 32/64비트. 접힌 텍스트 전체를 펼쳐 읽었다. 이미지 자체의 세부 해독까지 완료한 것으로 기록하지 않는다.
- 대응: content/ch01.js b01~b06 및 더 알아보기. 기존 푸드트럭 비유를 유지했다.
- 정정: CU의 명령 실행 제어와 OS의 작업 스케줄링 구별. PC는 주소를 추적하며 명령 자체의 보관 공간과 구별. 어셈블리어는 기계어의 사람이 읽는 표현. GHz는 주기 수이며 명령 수와 동일하지 않음. L2/L3가 항상 CPU 밖에 있지는 않음. SoC와 CPU, 메모리 공유와 소프트웨어 호환성을 구별. 오래된 M1 사례에는 2020년을 명시했다.
- 근거: 학생용 원고의 Intel 클럭·캐시 자료, Arm 어셈블리 설명, Apple 2020년 M1 발표 링크 참조.

## CH02-L01

- 근거: MIT OpenCourseWare의 점근적 복잡도 자료, MDN의 JavaScript 메모리 관리, OSTEP의 메모리 가상화·관리 설명. 실습은 4B 고정 폭 값 모형과 최근20개 목록의 실제 추가·제거를 수행한다.

## CH05-L02

- 기존 초안 검토: 완료
- 확인: CPU·메모리·네트워크 시간 자원, 타임아웃, Big-O와 대표 성장률, 자료구조·정렬 알고리즘 비용, 스케줄링, 시간 제한과 네트워크 오류의 접힌 텍스트를 모두 펼쳐 읽었다.
- 정정: 측정한 실행 시간과 연산 횟수 증가를 구별. Big-O가 언제나 최악, Ω가 최선, Θ가 평균이라는 설명을 수정. O(log n)의 로그 밑이 반드시 2라는 단정을 점근 표기에서 밑은 상수배 차이라는 설명으로 보완. BST가 항상 O(log n)이라는 단정을 균형 조건과 분리. 1초당 연산 횟수·입력 한계를 보편 상수로 외우지 않게 했다.
- 근거: NIST DADS의 이진 탐색, MIT OpenCourseWare 알고리즘 자료, OSTEP의 CPU·메모리 자원 설명. 브라우저 실습은 비교 사건을 직접 세고 정렬되지 않은 이진 탐색을 차단하며 전송 시간과 RTT를 따로 계산한다.

## CH06-L01

- 기존 초안 검토: 완료
- 확인: LAN·WAN, 클라이언트·서버, OSI 탄생 배경과 계층별 역할, 계층별 통신 단위, 캡슐화·디캡슐화, TCP/IP 모델과 패킷의 접힌 텍스트를 모두 펼쳐 읽었다.
- 정정: 클라이언트·서버를 장비 종류가 아닌 역할로 설명. OSI와 TCP/IP를 역사·계층 수·기능의 일대일 대응으로 단정하지 않음. MAC 주소를 영구적·세계적 개인번호로 설명하지 않음. 데이터 링크가 언제나 순서 복구와 재전송을 보장한다는 표현을 제거. IP 전달과 TCP의 신뢰성·순서 제공을 분리했다.
- 근거: ISO/IEC 7498-1 OSI 기본 참조 모델, IETF RFC1122의 인터넷 호스트 계층, RFC9293의 TCP. 실습은 메시지 포장·복원과 순서 변경·누락 조각을 실제 상태 전이로 수행한다.

## CH06-L02

- 기존 초안 검토: 완료
- 확인: IP·포트·DNS·패킷·TCP/IP, HTTP 개요·메서드·상태코드·통신 흐름, HTTPS·인증서·Handshake의 접힌 텍스트를 모두 펼쳐 읽었다.
- 정정: IP가 장치마다 영구적으로 하나인 고유번호라는 단순화를 제거. HTTP를 무조건 요청마다 연결 종료·단방향·TCP 전용으로 설명하지 않음. 메서드의 안전·멱등 의미와 응답 코드 반복을 구별. HTTP404·500 응답과 연결 실패를 분리. 최신 TLS를 서버 공개키로 대칭키 하나를 전달하는 고정 RSA 절차로 설명하지 않고 인증서 검증·키 합의·보호 통신 역할로 설명했다.
- 근거: WHATWG URL Standard, IETF RFC9110 HTTP Semantics, RFC8446 TLS1.3, MDN HTTP 개요. 실습은 브라우저 URL 파서와 결정적 모의 서버를 사용하며 실제 암호문을 흉내 내지 않는다.

## CH07-L01

- 명세: 탐색 전제, 단순 정렬, 분할 정렬, 안정성, 입력 상태별 비용을 기존 단원의 질문형 흐름으로 확장했다.
- 정정: 정렬의 정확성을 비내림차순 하나로만 설명하지 않고 입력 항목 보존을 함께 검사한다. 이진 탐색의 정렬 전제를 명시하고 준비·유지 비용을 분리한다. 삽입 정렬의 최악 Θ(n²)과 거의 정렬된 입력의 적은 이동을 구별한다. 병합 정렬의 안정성은 동률 처리 구현에 달렸으며, 퀵 정렬의 평균 Θ(n log n)과 치우친 분할의 최악 Θ(n²)을 구별했다.
- 근거: NIST Dictionary of Algorithms and Data Structures의 Sort·Insertion Sort, MIT OpenCourseWare의 Insertion Sort and Merge Sort. 실습은 식별자가 붙은 항목으로 실제 안정 삽입·버블 정렬을 한 비교·이동씩 수행하고 순서·다중집합 보존·동률 순서를 검사한다.

## CH07-L02

- 정정: 탐욕법을 항상 최적이거나 단순히 가장 큰 값을 고르는 방법으로 일반화하지 않는다. 가지치기는 안전한 제약·경계 근거가 필요함을 명시한다. 분할 정복의 비교적 독립적인 부분 문제와 DP의 겹치는 부분 문제를 구별하고, DP에 상태·점화식·기본값·계산 순서가 필요함을 설명했다.

## CH08-L01

- 명세: 루트·부모·자식·깊이·높이, 전위·중위·후위 순회, BST의 탐색과 편향, 균형 필요성, 최소 힙과 우선순위 큐를 한 흐름으로 연결했다.
- 정정: 높이의 간선 수·노드 수 정의가 문맥에 따라 다를 수 있어 이 교안은 간선 수 기준임을 명시했다. BST 탐색을 언제나 O(log n)으로 설명하지 않고 높이 h에 대한 O(h)와 균형 보장을 구별했다. 최소 힙은 루트의 최소와 부모-자식 관계를 보장하지만 배열 전체 정렬을 보장하지 않음을 설명했다.
- 근거: MIT OpenCourseWare 6.006의 Binary Trees·AVL·Binary Heaps 강의 노트, NIST Dictionary of Algorithms and Data Structures. 실습은 중복 없는 실제 BST를 만들고 삽입·탐색 경로와 세 순회를 수행한다.

## CH08-L02

- 명세: 정점·간선·방향·가중치, 인접 리스트·행렬, BFS·DFS·방문 기록, 다익스트라, 위상 정렬을 질문별로 구별했다.
- 정정: BFS의 최단 경로 보장은 가중치 없는 최소 간선 수 기준으로 한정했다. DFS가 일반적인 최단 경로를 보장하지 않음을 명시했다. 다익스트라는 음이 아닌 간선 가중치를 전제로 하며, 음수 간선이 있는 최단 경로 문제 자체가 모두 불가능하다는 오해를 막았다. 위상 정렬은 방향 비순환 그래프에서 가능하고 결과가 하나뿐일 필요가 없음을 설명했다.
- 근거: MIT OpenCourseWare 6.006의 BFS·DFS·Dijkstra 강의와 문제 풀이 자료. 실습은 A-B1, B-C1, A-C5에서 BFS의 A-C 1개 간선과 다익스트라의 A-B-C 비용2를 실제 상태 전이로 계산하고 연결되지 않은 D와 음수 비용을 별도 처리한다.

## CH09-L01

- 명세: 운영체제와 커널, 사용자·커널 모드, 시스템 콜의 진입·검사·대기·복귀, 인터럽트·예외·문맥 교환을 하나의 파일 읽기 흐름으로 연결했다.
- 정정: 커널을 운영체제 전체와 같은 말로 쓰지 않는다. 시스템 콜을 일반 함수 호출과 동일하게 설명하지 않고 보호된 진입 절차와 복귀 문맥을 명시했다. 커널 모드 진입과 프로세스 문맥 교환을 구별하고, 입출력 완료 뒤 READY가 즉시 RUNNING을 보장하지 않음을 설명했다. 인터럽트·예외·시스템 콜은 시작 원인과 동기성, CPU별 용어 차이를 함께 적었다.
- 근거: OSTEP 한국어판의 제한적 직접 실행 원리, Linux read(2), Intel 시스템 프로그래밍 자료. 실습은 정상 읽기·권한 거부·사용자 모드 직접 장치 접근을 서로 다른 결과로 실행한다.

## CH09-L02

- 명세: 드라이버, 폴링·인터럽트·DMA, 블로킹·논블로킹과 동기·비동기, 파이프·소켓·공유 메모리 IPC를 버퍼의 기다림과 종료 규칙으로 연결했다.
- 정정: DMA를 CPU가 전혀 관여하지 않는 전송으로 설명하지 않는다. 블로킹/논블로킹과 동기/비동기를 하나의 같은 축으로 고정하지 않고 반환 시점과 완료 전달 방식을 구체적으로 적는다. POSIX 파이프는 메시지 경계가 없는 바이트 스트림이며, 버퍼를 비우고 모든 쓰기 끝이 닫힌 뒤 EOF가 보이고 모든 읽기 끝이 닫힌 뒤 쓰기는 SIGPIPE/EPIPE와 관련됨을 반영했다. 공유 메모리에도 별도 동기화가 필요하다.
- 근거: OSTEP 한국어판의 입출력 장치, Linux pipe(7), Linux Kernel DMA mapping guide. 실습은 용량 두 칸에서 A·B·C FIFO, 가득 참 대기, 빈 파이프 대기, EOF와 EPIPE 모형을 실행한다.

## CH10-L01

- 명세: 가상·물리 주소, 페이지·프레임·페이지 테이블, TLB, 요구 페이징과 페이지 폴트, FIFO·LRU 교체와 스래싱을 주소 계산과 참조열로 연결했다.
- 정정: TLB 미스를 페이지 폴트와 같은 사건으로 설명하지 않는다. 페이지 폴트가 항상 디스크 읽기를 일으키거나 항상 정상 복구된다고 일반화하지 않는다. LRU는 최근 참조 순서를 갱신하지만 FIFO는 히트 때 들어온 순서를 바꾸지 않음을 분리했고, 실제 운영체제가 정확한 LRU 대신 Clock 같은 근사를 쓸 수 있음을 명시했다.
- 근거: OSTEP 한국어판의 페이징·TLB·물리 메모리 초과 정책, Linux Kernel Page Tables. 실습은 2053→페이지2·오프셋5→프레임7→7173을 계산하고, 요청1·2·3·1·4에서 FIFO 희생1과 LRU 희생2를 실제 상태 전이로 만든다.

## CH10-L02

- 명세: 디렉터리 이름·inode 예·데이터 블록, 0바이트 파일, 블록 할당과 빈 공간, 페이지 캐시·writeback·동기화, 저널 커밋과 장애 복구를 연결했다.
- 정정: 파일 이름이 inode 안에 저장된다고 일반화하지 않고 디렉터리 항목의 이름→inode 번호 연결로 설명한다. write 성공과 영구 저장 완료를 구별하고, fsync의 파일 데이터·메타데이터 범위와 디렉터리 항목 지속성이 별도일 수 있음을 적었다. 저널링이 모든 파일 시스템에서 전체 데이터를 같은 방식으로 보장한다고 설명하지 않는다.
- 근거: OSTEP 한국어판의 파일·디렉터리와 파일 시스템 구현, OSTEP Crash Consistency and Journaling, Linux fsync(2). 실습은 단순화한 전체 데이터 저널에서 커밋 전 장애는A, 커밋 후 최종 반영 전 장애는B를 복구하며 0바이트와 ENOSPC를 별도 처리한다.

## CH11-L02

- 명세: 교착의 네 필요 조건, 자원 할당·대기 순환, 전역 자원 획득 순서, 교착 예방, 기아·공정성·라이브락, 안전성과 진행성을 연결했다.
- 정정: 네 조건이 가능한 시스템을 현재 교착 상태와 동일시하지 않고 실제 소유·대기 고리를 확인한다. 긴 대기와 교착을 구별하고, 상호 배제만 지킨다고 각 작업의 완료·공정성까지 보장되는 것은 아님을 명시했다. 교착·기아·라이브락을 상태 변화와 완료 작업의 범위로 구별했다.
- 근거: OSTEP Common Concurrency Problems와 Oracle Concurrency의 Starvation and Livelock 설명. 실습은 A:X→Y·B:Y→X의 순환과 모두 X→Y의 완료를 비교하고, 강제 자원 탈취를 거부하며 라이브락·기아 상태를 따로 표시한다.

## CH12-L01

- 명세: 엔터티·속성·관계, 기본키·외래키, 카디널리티, 다대다 연결 표, 변경 이상, 정규화와 의도적 비정규화를 도서관 관계로 연결했다.
