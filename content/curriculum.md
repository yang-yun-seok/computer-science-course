# Computer Science — 1강부터 부록까지 전체 커리큘럼

기존 노션의 6개 대단원과 12개 소단원은 1강으로 유지한다. 그 뒤에 **2강 6개, 3강 8개, 부록 4개의 대단원**을 추가한다. 전체는 **24개 대단원·48개 소단원**으로 구성한다.

이 문서는 대단원 확장 목차와 학습 범위, 실습 설계다. 각 단원에 표시한 브라우저 실습은 앞으로 HTML에 구현할 내용이다. 기초 단원의 이해를 바탕으로 구조·동작·한계·설계 판단까지 단계적으로 깊어진다.

각 대단원은 원본처럼 관련된 두 소단원을 묶는다. 설명 방식도 ‘이전 내용 복습 → 친숙한 예시 → 개념과 구조 → 동작과 활용 → 정리와 실습’으로 이어간다. 학생은 실습의 결과를 먼저 예상하고, 실행 뒤 왜 그런 결과가 나왔는지 설명한다.

| 단계 | 대단원 | 학습의 깊이 |
| --- | --- | --- |
| 1강 | 1~6 | 구성 요소와 용어를 알고 기본 동작을 설명한다. |
| 2강 | 7~12 | 자료를 다루고 자원을 관리하는 방법을 비교한다. |
| 3강 | 13~20 | 내부 구조, 실행 원리, 동시성·장애 상황의 제약을 이해한다. |
| 부록 | 21~24 | 요구사항에 맞게 시스템을 설계하고 검증·운영한다. |

## 1. CPU와 메모리

### 1-1. CPU 와 메모리

기존 페이지 유지. 컴퓨터 구성, 입출력 장치, CPU 구성과 동작, 주기억장치·보조기억장치, 부품 사이의 데이터 이동을 학습한다.

### 1-2. CPU 와 메모리 심화

기존 페이지 유지. 스케쥴링 소개와 종류, 캐시와 지역성, 캐시히트·미스, 메모리 할당을 학습한다. 여기서의 ‘심화’는 첫 대단원 안의 심화이며, 후반부에서 다룰 가상 메모리·CPU 파이프라인 등의 선수 지식이 된다.

**브라우저 실습**: 푸드트럭 모형으로 명령과 데이터 이동을 따라가고, 캐시 칸 수와 요청 순서를 바꾸어 히트·미스를 비교한다.

## 2. 프로세스와 쓰레드

### 2-1. 프로세스 생명주기와 프로세스 메모리

기존 페이지 유지. 프로그램과 프로세스, 준비·수행·대기 상태, 스케줄링과 문맥 교환, 프로세스 주소 공간을 학습한다.

### 2-2. 쓰레드와 쓰레드 풀

기존 페이지 유지. 프로세스와 쓰레드의 차이, 공유·개별 영역, 멀티 구성, 쓰레드 풀, 동시성과 병렬성을 학습한다.

**브라우저 실습**: 작업을 실행·대기·재개하고, 작업자 수가 제한된 풀에서 작업 큐가 어떻게 처리되는지 관찰한다.

## 3. DB와 DBMS

### 3-1. DB(데이터베이스) 구조와 유형

기존 페이지 유지. 저장장치와 데이터, DB와 DBMS, 파일 관리와 데이터 관리, 관계형·비관계형 데이터 모델을 학습한다.

### 3-2. DBMS(데이터베이스 관리시스템)의 기능과 종류

기존 페이지 유지. DBMS 용어와 요구사항, 트랜잭션의 기본 개념, RDB와 NoSQL의 특징과 종류를 학습한다.

**브라우저 실습**: 도서관 데이터를 찾아보고 수정하며, 대출 처리의 성공·실패를 간단한 데이터 상태 모형으로 확인한다.

## 4. 자료와 자료구조

### 4-1. 자료의 저장과 표현

기존 페이지 유지. 비트·바이트·이진수, 문자·숫자·멀티미디어의 표현을 학습한다.

### 4-2. 자료구조의 동작과 활용

기존 페이지 유지. 배열, 연결 리스트, 동적 배열, 큐·스택·덱, 해시 테이블과 집합의 구조와 사용 예를 학습한다.

**브라우저 실습**: 비트 스위치와 문자 변환기를 조작하고, 같은 데이터를 서로 다른 자료구조에 넣고 꺼내 본다.

## 5. 자원과 자원 관리

### 5-1. 공간 자원과 공간 복잡도

기존 페이지 유지. 메모리·저장장치의 공간, 입력 크기와 추가 공간, 자료형과 배열의 한계를 학습한다.

### 5-2. 시간 자원과 시간 복잡도

기존 페이지 유지. CPU·메모리·네트워크에서 드는 시간, 작업 횟수의 증가, 자료구조·알고리즘별 비용을 학습한다.

**브라우저 실습**: 입력 크기를 바꾸며 필요한 공간과 비교 횟수를 관찰하고, 캐시를 사용했을 때의 시간·공간 교환을 비교한다.

## 6. 네트워크와 OSI 7계층

### 6-1. OSI 7계층

기존 페이지 유지. 네트워크, 클라이언트·서버, 계층별 역할, 통신 규칙과 단위, TCP/IP 모델을 학습한다.

### 6-2. HTTP/HTTPS

기존 페이지 유지. IP·포트·DNS·패킷, HTTP 메소드와 상태코드, 요청·응답, HTTPS와 TLS 연결 과정을 학습한다.

**브라우저 실습**: 메시지의 전달 과정을 따라가고, 도서 정보 조회 요청의 성공·오류·응답 대기 상황을 관찰한다.

## 7. 알고리즘과 문제 해결

**1강에서 이어지는 질문**: 자료를 저장하는 방법을 알았다면, 원하는 답은 어떤 절차로 찾을까?

### 7-1. 탐색과 정렬 알고리즘

- 순차 탐색과 이진 탐색의 동작 및 전제 조건
- 버블·삽입 정렬에서 비교와 이동이 발생하는 위치
- 병합·퀵 정렬이 문제를 나누는 방법
- 안정 정렬의 의미와 중복된 값의 처리
- 입력 상태에 따른 실제 작업 횟수와 최악·평균 분석

### 7-2. 알고리즘 설계 전략

- 완전 탐색과 가지치기
- 분할 정복과 재귀
- 탐욕법의 선택이 정답으로 이어지는 조건
- 동적 계획법의 상태·전이·중복 부분 문제
- 같은 문제의 서로 다른 풀이와 시간·공간 비교

**브라우저 실습**: 숫자 막대 정렬을 한 단계씩 실행한다. 동전 종류를 바꾸며 탐욕 선택이 실패하는 경우를 보고, 동적 계획법 표가 채워지는 과정을 비교한다.

**학습 결과**: 알고리즘 이름뿐 아니라 입력 조건, 정확성의 이유, 비용의 차이를 설명한다. 먼저 4·5단원을 학습한다.

## 8. 트리와 그래프

**1강에서 이어지는 질문**: 줄 세운 데이터만으로 표현하기 어려운 계층과 연결은 어떻게 다룰까?

### 8-1. 트리의 구조와 탐색

- 루트·부모·자식·깊이·높이
- 전위·중위·후위 순회
- 이진 탐색 트리와 편향된 트리
- 균형 유지의 필요성
- 힙과 우선순위 큐의 동작

### 8-2. 그래프와 경로 탐색

- 정점·간선·방향·가중치
- 인접 행렬과 인접 리스트

**브라우저 실습**: 노드를 추가해 트리가 기울어지는 모습을 본다. 지도에서 간선과 비용을 바꾸며 BFS와 다익스트라의 선택 과정을 비교한다.

**학습 결과**: 계층·관계·우선순위를 알맞은 구조로 모델링하고 탐색 방법을 고른다. 먼저 4·5·7단원을 학습한다.

## 9. 운영체제와 시스템 자원

**1강에서 이어지는 질문**: 프로세스들이 하드웨어를 안전하게 나눠 쓰도록 누가 어떤 규칙을 적용할까?

### 9-1. 커널과 시스템 콜

- 운영체제와 커널의 역할
- 사용자 모드와 커널 모드
- 시스템 콜의 요청·처리·복귀
- 인터럽트와 예외
- 실행 기회 배분과 문맥 교환의 연결

### 9-2. 입출력과 프로세스 간 통신

- 장치 드라이버와 입출력 요청
- 폴링·인터럽트·DMA의 역할

**브라우저 실습**: 파일 읽기 요청이 사용자 코드에서 커널과 장치를 거쳐 돌아오는 모형을 실행한다. 폴링과 알림 방식의 상태 확인 횟수를 비교한다.

**학습 결과**: ‘운영체제가 관리한다’는 설명을 실제 요청 경로와 보호 경계로 풀어 설명한다. 먼저 1·2단원을 학습한다. 범위 참고: [OSTEP 운영체제 교재](https://pages.cs.wisc.edu/~remzi/OSTEP/).

## 10. 가상 메모리와 파일 시스템

**1강에서 이어지는 질문**: 프로그램이 보는 주소와 실제 메모리는 어떻게 연결되고, 파일은 저장장치 어디에 놓일까?

### 10-1. 가상 메모리와 주소 변환

- 페이지·프레임·페이지 테이블

- 페이지 폴트와 요구 페이징
- 페이지 교체와 스래싱의 원리

### 10-2. 파일 시스템과 저장장치 관리

- 파일·디렉터리·메타데이터
- 파일 이름과 실제 데이터 위치의 관계
- inode 등 파일 관리 구조의 예
- 블록 할당과 빈 공간 관리
- 버퍼링·쓰기 반영·저널링과 장애 복구

**브라우저 실습**: 가상 주소를 페이지 번호와 오프셋으로 나누어 변환한다. 같은 페이지 요청을 여러 교체 정책에 넣어 폴트 수를 비교한다. 파일 수정 중 모의 장애를 넣어 기록 복구를 살펴본다.

**학습 결과**: 주소·메모리 용량·디스크 저장을 구별하고 접근 실패와 복구 과정을 설명한다. 먼저 1·2·5·9단원을 학습한다.

- 뮤텍스·세마포어·조건 변수
- 생산자·소비자와 제한된 버퍼
- 잠금의 범위와 경합 비용

### 11-2. 교착 상태와 진행 보장

- 자원 획득 순서와 예방

**브라우저 실습**: 두 작업의 읽기·변경·저장 순서를 조작해 갱신 손실을 만든다. 잠금 모형으로 문제를 해결한 뒤, 두 자원을 서로 다른 순서로 얻어 교착 상태를 만들어 본다.

**학습 결과**: ‘쓰레드를 많이 쓰면 빠르다’를 넘어 공유 데이터의 정확성과 진행 가능성을 판단한다. 먼저 2·9단원을 학습한다.

## 12. 데이터 모델링과 SQL

**1강에서 이어지는 질문**: 실제 서비스의 정보를 어떤 표로 나누고 어떻게 질문해야 할까?

**학습 결과**: 기록을 일관되게 모델링하고 질문에 맞는 조회를 구성한다. 먼저 3·4단원을 학습한다.

**학습 결과**: 인덱스 유무만 보지 않고 데이터 분포·작업량·실행 계획을 함께 판단한다. 먼저 3·5·8·12단원을 학습한다. 범위 참고: [CMU 데이터베이스 시스템 강의 구성](https://15445.courses.cs.cmu.edu/fall2025/schedule.html).

## 대단원 사이의 확장 경로

| 기존 출발점 | 2강·3강 확장 경로 |
| --- | --- |
| CPU와 메모리 | 9 운영체제 → 10 가상 메모리·파일 시스템 → 18 프로그램 실행 → 19 컴퓨터 구조·병렬 처리 |
| 프로세스와 쓰레드 | 9 운영체제 → 11 동기화 → 14 DB 동시 실행 → 20 분산 시스템 |
| DB와 DBMS | 12 모델링·SQL → 13 DB 내부 구조 → 14 트랜잭션·일관성 → 20 복제·합의 |
| 자료와 자료구조 | 7 알고리즘 → 8 트리·그래프 → 13 인덱스 → 18 AST·실행 구조 |
| 자원과 자원 관리 | 7 알고리즘 비용 → 10 메모리 관리 → 19 병렬 성능 → 21 확장성 → 24 운영 지표 |
| 네트워크와 OSI 7계층 | 15 인터넷 프로토콜 → 16 웹·브라우저 → 17 보안 → 20 분산 시스템 → 21 시스템 설계 |

이 표는 주제의 연결을 보여준다. 수업을 특정 경로만 따라 진행할 때는 각 대단원에 적은 선수 단원도 함께 확인한다. 번호 순서는 전체 과정을 순차적으로 배울 수 있게 배치했으며, 한 대단원이 수업 한 번의 분량이라는 뜻은 아니다.

## HTML 학습 자료로 만드는 공통 기준

1. 대단원 첫 화면에는 ‘앞에서 배운 것’과 ‘이번에 더 이해할 것’을 짧게 연결한다.
2. 각 소단원은 개념·구조·동작·활용 순서로 설명하고, 심화 용어는 필요한 시점에 소개한다.
3. 실습은 한 번에 한 조건을 바꾸게 하고, 입력·중간 상태·결과를 함께 표시한다.
4. 단계 실행·자동 실행·일시 정지·초기화를 제공한다. 자동 실행 속도는 학습용이며 실제 성능과 구별한다.
5. 알고리즘, 자료 변환, 간단한 파서, 통계 계산 등은 실제 브라우저 계산으로 제공한다.
6. CPU·운영체제·분산 서버·통신 계층 등은 보장과 생략 조건을 명시한 학습 모형으로 제공한다.
7. 실습마다 정상 상황에 이어 경계·실패 상황 하나를 넣고, 왜 실패하는지 설명한다.
8. 확인 문제는 용어 암기와 함께 결과 예측, 원인 설명, 설계 선택을 포함한다.
9. 기본 설명은 처음부터 보이고, 수식·구현 세부·추가 알고리즘은 ‘더 알아보기’에 둔다.
10. 수업의 핵심 목표는 학생이 ‘왜 이 구조와 규칙이 필요한가’를 자기 말로 설명하는 것이다.
